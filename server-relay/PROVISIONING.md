# Provisioning device credentials

By default the relay admits every device: there is nothing to provision. Anyone who can reach the relay URL and knows a Desk ID can register as that ID, and Windows hosts accept sessions without a prompt, so keep the relay URL private.

Optional per-device tokens: set `OPENDESK_DEVICE_CREDENTIALS` in the relay environment, e.g. `{"123456789":{"token":"<random secret, at least 32 chars>","admin":true}}`. Once it is set, only listed Desk IDs may register, and only the relay's `admin` flag grants host-list access. Put each device's token in `%APPDATA%\OpenDesk\config.json` as `device_token` (or `OPENDESK_DEVICE_TOKEN`); on Android, under Gateway settings.

Use WSS through a trusted TLS terminator or loopback WebSocket; direct unencrypted non-loopback WebSocket connections are rejected unless `OPENDESK_TLS_PROXY=1` says TLS ends at a proxy in front of the relay.

SHA-256 is sent with the final file message. New receivers reject missing or mismatched digests, so old senders cannot send files to new receivers. This detects corruption, not malicious changes made by an authenticated sender. Desktop clients advertise the `file-ack` capability: the receiver answers `end` with an ACK/NACK, and the sender shows "Terkirim" only after a positive ACK (120-second timeout). Peers without `file-ack` (currently Android) get no ACK, so the sender only reports that the bytes left its socket. There is no retry or resume: a dropped relay connection fails every transfer on it. Copy-paste between peers that both advertise `file-offer` (and a relay that lists it in its caps) is lazy, like AnyDesk: copying sends only an `offer` with names and sizes, the other side exposes them as virtual clipboard files, and each paste sends a `pull` that starts a normal granted transfer under the receiver-chosen ID. `offer`/`pull` are routed only inside an active session. Folders are not offered yet. `p2p-signal` is limited to an active paired session, 4096-byte messages and 10 messages/s per connection. Desktop clients use it to exchange a Noise handshake and UDP candidates, then send video, audio and input directly over encrypted UDP, falling back to the relay automatically (design: `rencana-implementasi.md`). Kill switches: set `OPENDESK_P2P_DISABLED=1` on the relay, or `OPENDESK_P2P=0` on a client, to keep every session on the relay. `OPENDESK_STUN` sets the client's STUN server (`host:port`, default `stun.l.google.com:19302`, `off` disables public candidates).
